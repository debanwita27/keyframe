# Move vocabulary — proposed additions (shape-masking + gaps)

MOVE_VOCAB.md currently has exactly two mask moves, and both are rectangular:
`maskWipeUp` (`overflow:hidden` box, content translates) and `maskWipeSide`
(`clip-path: inset()` sweep). The reference corpus (`refs/specs/*.yaml`) contains a
much richer shape-masking vocabulary that was never captured — masks whose *shape*
is the animated thing, masks that are the subject rather than a reveal device, and
systematic material/treatment swapping. This file proposes additions in the exact
table format of MOVE_VOCAB.md. All frame counts and easing names are normalised to
30fps regardless of a source spec's native fps. Every entry cites the spec it is
grounded in.

---

## Shape-driven mask reveals
Masks whose outline is itself circular, polygonal, or morphing — not a straight edge.

| move | params | description |
|---|---|---|
| `irisMaskReveal` | `dur_f=16, r_pct=[0,140], origin={x%,y%}, ease=expoOut` | Content revealed through a circular `clip-path` expanding from a point (often off-centre, e.g. bottom-right over a logo bug) to fully uncover the frame. From `B_galactic-motion-art`'s `irisReveal` (13f, r 0→64px over a fixed corner) and the eye-iris endpoint of `B_editors-loop-3d-camera`'s `shapeMorphCollapse`. **Remotion recipe:** `clip-path: circle(${r}% at ${x}% ${y}%)` on a wrapper holding the alternate/next layer; interpolate `r` only, never crossfade opacity underneath it. |
| `blobMaskReveal` | `dur_f=18, ease=backOut, scale=[0,1.15,1]` | Like `irisMaskReveal` but the mask is an irregular rounded-blob SVG path rather than a perfect circle — reads as "liquid" instead of "mechanical." Generalised from the corpus's shape-morph family (`B_editors-loop-3d-camera`, `A_motion-explainer-snippet`'s canyon-silhouette reveal). **Remotion recipe:** SVG `<mask>` with a pre-authored blob `<path>`; animate the mask group's `scale` from its own centroid via `transform-box: fill-box; transform-origin: center`. |
| `travelingShapeWipe` | `dur_f=20, dir=l→r, shape=triangle\|chevron\|blob, ease=expoInOut` | A non-rectangular shape (not a straight vertical/horizontal edge) sweeps across the frame; content is revealed behind it as it passes and re-hidden by an identical shape following it — a two-shape sandwich reveal. Generalised from `A_motion-explainer-snippet`'s `vanishThroughGap` (an object progressively occluded by a *static* foreground shape via z-order clipping, not opacity) run forward as a reveal instead of backward as an occlusion. **Remotion recipe:** two absolutely-positioned `<div>`s sharing one `clip-path: polygon(...)` shape, back layer static, front layer's polygon points translated across the frame via `interpolate()`; content sits z-indexed between them. |
| `maskShapeMorph` | `dur_f=20, stages=[shapeA,shapeB,...], ease=expoInOut` | The mask's own outline morphs between named shape stages (square → circle → eye → ribbon) while it reveals/occludes content — the reveal *device* is the visual event, not just what's underneath. Direct generalisation of `B_editors-loop-3d-camera`'s `shapeMorphCollapse` and `B_chromatic-logo-2d3d`'s `bloom-invert-morph-transition` (SVG path-morph from a negative-space star silhouette to a flat icon). **Remotion recipe:** normalise all stage paths to equal point-count; `flubber.interpolate(pathA, pathB)` driven by one progress value; use the interpolated `d` as an SVG `<clipPath>`/`<mask>` referenced via `clip-path: url(#id)`. **Difficulty: hard** (path point-count normalisation must be planned before final art is drawn). |
| `concentricRingMask` | `dur_f=21, ring_count=5, rotate_period_f=300, ease=linear (ambient) / expoOut (reveal)` | Reveal/occlude via a set of expanding or slowly rotating concentric rings rather than one hard edge — reads as "portal / iris / eclipse." From `A_sparkle-vertical`'s `portalRingPulse` and `B_galactic-motion-art`'s `irisReveal`. **Remotion recipe:** N concentric SVG `<circle>` strokes sharing one `<radialGradient>`; drive one ring's radius via `interpolate()` for the reveal variant, or rotate the whole `<g>` at `period_f=300` (linear) for the ambient/idle variant. |
| `nestedFrameTunnelMask` | `frames_per_pass=22, passes=3, squares_per_pass=4, scale_growth_per_square=1.6, palette_swap=hard (step function, not crossfade)` | A forward dolly through repeating nested-square/ring "picture frame" geometry, built once and reused for N passes; each pass boundary hard-swaps the palette via CSS custom properties (`paletteIndex = Math.floor(frame/22)`) so it reads as arriving somewhere new though the camera never stops. From `A_sparkle-vertical`'s `kaleidoTunnelZoom` and `B_editors-loop-3d-camera`'s `portalDive`. **Remotion recipe:** `perspective` parent + `translateZ` per layer (CSS 3D is sufficient for the nested-square version, `difficulty: hard`). **Needs WebGL/three.js** only for the ribbon-plank variant (`A_sparkle-vertical`'s `ribbonTunnelFly`) whose per-plank hue is driven by a fragment-shader `uHue` uniform rather than CSS. |

## Mask-as-subject (the mask/shape IS the animated content, not a reveal device)
The mask's own transformation is the thing being watched, independent of any
underlying content it might also be hiding or showing.

| move | params | description |
|---|---|---|
| `fillToStrokeCrossfade` | `dur_f=24, ease=expoInOut` | A shape (or group — e.g. a logo's circle cluster) crossfades from a solid-fill rendering to an outline-only stroke rendering of the **identical** geometry: no morph, just `fill-opacity: 1→0` on one layer while `stroke-opacity: 0→1` on a stacked duplicate. Reads as the shape "dematerialising" into a lighter version of itself. From `B_logo-wip`'s `fillToStroke` and `B_chromatic-logo-2d3d`'s `flat-icon-vector-anchor-orbit`. **Remotion recipe:** two SVG `<g>` groups with identical `<circle>`/`<path>` children, one `fill`-only, one `stroke`-only; interpolate both opacities over the same window, same easing. |
| `anchorRingOrbit` | `dur_f=42, point_count=14, rotate_deg=[0,90], children_counter_rotate=false` | A ring of small vector "bezier-handle" points (square/circle caps + thin connector lines) slowly rotates around an otherwise-static mark — evokes a vector-editor control-point overlay. The decoration *is* the shot; the mark underneath never moves. From `B_chromatic-logo-2d3d`'s `flat-icon-vector-anchor-orbit`. **Remotion recipe:** place N points at polar coordinates around the mark's bounding box, wrap in one parent `transform: rotate(deg)`, `deg = interpolate(frame,[start,end],[0,90])`. Individual points do **not** counter-rotate — they visibly tumble with the ring. |
| `glitchMaterialMorph` | `dur_f=35, variant_count=6, swap_interval_f=[4,5,5,5,4,5,7] (seeded-random order, never periodic), hold_camera=true` | Camera and silhouette never move; only the object's surface material/texture pass hard-swaps between N pre-rendered variants at an irregular ~4-7f interval. The surface *is* the subject — "this thing is alive" reads purely from material flicker, cheaper than any camera move. From `B_trippy-abstract-type`. **Remotion recipe:** stack N image/video layers in one container; index with `Math.floor(frame / interval)` into a seeded shuffle array (not raw frame — swaps must look chaotic, not periodic); crossfade 1-2f to hide the swap. |
| `holoEchoOutline` | `copies=3, scale=[1.15,1.35,1.55], colors=[hueA,hueB,hueC], opacity=[0.35,0.25,0.15]` | The same in-progress stroke/mask path is rendered N extra times, scaled up around its own centroid, hue-shifted, with falling opacity — all driven by the identical progress value as the main path. Fakes chromatic-dispersion/holographic-foil fringing for the cost of duplicating one SVG path. From `B_logo-holo`. Distinct from MOVE_VOCAB's `motionTrail`, which offsets echoes in **time** (2f apart) — these echoes are perfectly time-synced but offset in **scale and hue** instead. **Remotion recipe:** N `<path>` elements sharing one `d` and one `strokeDashoffset` driver, wrapped in `<g transform="scale(s)">` at the given scale/opacity, painted **behind** the full-opacity main path (paint order, not z-index). |

## Material / treatment swapping
Hard swaps on a fixed frame grid (no easing, reads as glitch/energy) vs. eased
crossfades (reads as a material transformation) — both are load-bearing in the
corpus and must be chosen deliberately, not interchangeably.

| move | params | description |
|---|---|---|
| `treatmentStutterSwap` | `step_f=4, states=[stateA,stateB,stateC,stateD]` | **Hard swap.** Quantise frame to `Math.floor(frame/step_f)*step_f` and index into an array of pre-built visual states with **zero** crossfade. Reads as "glitch/VHS-stutter" energy — smooth easing would undersell it. From `B_galactic-motion-art`'s `stutterHold` (4f holds cycling halftone→blackout→line-art→full-color) and `B_logo-wip`'s `twin-flash-alt-treatment` (two ≈4f@30fps hard flashes of an alt logo rendering). **Remotion recipe:** `const steppedFrame = Math.floor((frame-start)/step_f)*step_f`; swap opacity 1/0 between pre-rendered layers with zero transition. |
| `treatmentCrossfadeSwap` | `dur_f=24, ease=expoInOut` | **Eased swap** — the counterpart to `treatmentStutterSwap`. Two treatment layers of the *same* asset (e.g. duotone ink vs. full colour, chrome vs. panel-line skin) crossfade smoothly over `dur_f` instead of hard-cutting. Use when the swap should feel like a material transformation, not a glitch. From `B_chromatic-logo-2d3d`'s clean-chrome↔panel-line-skin passes. **Remotion recipe:** `opacity: interpolate(...)` 1→0 / 0→1 on two stacked pre-rendered layers, `expoInOut`, no hard step. |
| `paletteHardSwapPass` | `frames_per_pass=22, passes=3` | One reused geometry (e.g. a portal tunnel) gets its colour/gradient hard-swapped via CSS custom properties every `frames_per_pass` — `paletteIndex = Math.floor(frame/frames_per_pass)`, a step function, never interpolated — so each pass reads as "arriving somewhere new" though camera/geometry never resets. From `B_editors-loop-3d-camera`'s `portalDive`. **Remotion recipe:** `useMemo` a CSS custom-property set keyed by `paletteIndex`, apply via inline style; never interpolate between palette sets. |
| `fontFaceCycle` | `hold_f=[4..10] (varies per breathing arc), font_pool=10-12 display faces` | A single word's position/scale envelope is locked completely; only `font-family` is swapped on an interval, so **typeface itself** is the animated subject — no translation, no rotation, no scale ramp on the container. From `B_dynamic-typography-d3`'s `font-array-cycler`. **Remotion recipe:** `Math.floor(frame / holdFrames) % fonts.length` indexes a hardcoded font array; render outgoing/incoming stacked and crossfade per `fontSwapBlur` below. Pick 2-3 faces with very different intrinsic glyph widths so cycling family alone swings rendered width from comfortably-inside-frame to clipped-at-both-edges (`edge-bleed-crop`) — no manual per-font scale correction needed. |
| `fontSwapBlur` | `dur_f=6-10, blur_px=[0,18-34,0], skew_deg=[0,5-14,0], ease=expoInOut` | The transition mechanic for `fontFaceCycle`: a **horizontal-only** directional blur plus a small `skewX` shear ramps 0→peak→0, timed so peak-blur lands on the 50%-crossfade frame. Anisotropic blur reads as "smeared by motion," not "went out of focus" — disguises a zero-translation substitution as a fast pan/glitch. From `B_dynamic-typography-d3`. **Remotion recipe:** `filter: blur(Xpx)` (X peaks 18-34px) + `transform: skewX(Ydeg)` (Y peaks 5-14deg) on both outgoing and incoming font layers, offset ~2f from each other so their blur peaks overlap and hide the hard crossfade. Optionally render on twos (`heldFrame = Math.floor(frame/2)*2`) for a more mechanical, "designed" cadence. |
| `hueCycleMaterial` | `dur_f=36 (loop period), hue_deg=[0,260], saturate=1.4` | Continuous CSS `hue-rotate()` sweep plus a saturation boost on one glossy/chrome/iridescent asset — a full colour treatment for one `filter` line, no re-render, no regrade. From `B_trippy-abstract-type`'s `newMove-hueCycleMaterial`. **Remotion recipe:** `filter: hue-rotate(${(frame % period)/period * 260}deg) saturate(1.4)`. |

## Other move families the corpus demonstrates that MOVE_VOCAB lacks
Not masking, but load-bearing gaps surfaced by the same read.

| move | params | description |
|---|---|---|
| `logoToIconMorph` | `dur_f=26, ease=expoInOut, target_slot={x,y,scale}` | A hero-scale logo/mark shrinks and translates in place to become a small in-UI icon with zero cut — destination coordinates must equal the exact slot the real icon occupies in the UI it's morphing into. From `A_connect-to-figma-ui-anim`'s `morphToIcon`. **Remotion recipe:** one absolutely-positioned element; `transform: translate(x,y) scale(s)` interpolated hero→icon state with `expoInOut` (`cubic-bezier(0.87,0,0.13,1)`). |
| `shatterDisperse` → `fragmentsConverge` (paired) | disperse: `dur_f=24, fragment_count=10, spread_radius_pct=42, ease=expoOut` · converge: `dur_f=27, ease=springSnap, flatten_to_2d=true, overshoot_pct=5` | An object breaks into N pieces flying outward on independent seeded trajectories (disperse, `spring({damping:200,mass:0.6,stiffness:100})`), most fade, survivors travel inward and fuse into a target shape with a spring overshoot (converge, `spring({damping:14,mass:0.5,stiffness:180})`). The assembly-from-parts logo reveal. From `B_logo-sage-library`. |
| `liveCounterTick` | `dur_f=to-end-of-shot, rate=value_per_frame, jitter=optional sine` | A perpetually-incrementing numeric readout with **no** easing and no landing frame — a pure function of `frame` (`value = base + frame*rate + Math.sin(frame*k)*jitter`). Distinct from `counterUp`, which eases into a final resting value. Keeps a long static hold alive for the cost of zero `interpolate()` calls. From `A_micro-elements-animations`. |
| `bubbleDrift` / `chipFloat` | `amplitude_px=3-6, period_f=[90,130], phase_seed=per_index` | Ambient idle float for a cluster of independent sprites once their entrance settles: each gets its own period + phase offset seeded from its index, so the group bobs asynchronously instead of in lockstep. From `A_recent-motion-4k-vertical`'s `bubbleDrift` and `A_shipping-8-launch-videos`' `chipFloat`. **Remotion recipe:** `translateY = Math.sin((frame - entryFrame)/period + phaseSeed) * amp` per sprite, no shared clock. |
| `cursorTravelClick` + `stateSwap` (paired) | travel: `dur_f=10, click_at_f=constant, ease=expoOut` · swap: `dur_f=5, from/to label+color` | A synthetic pointer travels to a target control and performs a scale-pulse "click" exactly on `click_at_f` — the same constant that drives the control's resulting state change, so cause and effect can never drift apart on edit. From `A_connect-to-figma-ui-anim`. |
| `conveyorSlide` | settle: `spring(damping≈12,stiffness≈180)` to target offset + hold · burst: `step_px=340, step_f=3, hard cut, no easing` | A horizontal row of uniform-shaped cards driven by one offset function that switches between two modes — "settle" (spring to rest, readable) and "burst" (fixed-step hard cuts, high energy). Alternating them turns a fast multi-item montage into a pulse instead of either a flat scroll or unwatchable noise. From `A_showreel-snippet`. |
| `stepRelayAdvance` | `dur_f=0 (step function, not interpolated), row_h_px=110` | A vertical list of fixed-height rows snaps so index N is active (full colour, ringed, `scale(1.04)`) while neighbours go grayscale/50%-opacity — driven by shot number, not eased. Free progress indicator for any team/pipeline/steps narrative, zero new geometry per step. From `A_shipping-8-launch-videos`. |
| `particleFieldConnector` | `dot_count=35, depth_layers=3, amp_px=12, period_f=[200,320,450], caption_crossfade_f=10` | A persistent background layer (drifting dots across 3 parallax depth bands + one crossfading caption line) reused as connective tissue between hard cuts to otherwise-unrelated content, so a compilation reads as one authored reel. From `A_best-launch-reel-2026`. |
| `rackLoop` | `dur_f=27 (open), mirrored_out_f=16 (close), blur_px=[18,0], scale=[1.04,1]` | Background/content opens blurred and slightly scaled up, sharpens over `dur_f`; the identical curve replays in reverse at the very end so frame 0 and the final frame match pixel-for-pixel and the loop seam is imperceptible. From `A_recent-motion-4k-vertical`. |
| `wordCycleSettle` | `cycle_words_per_col=3, swap_every_f=5, settle_stagger_f=5, ease=expoOut` | For N independent text columns/slots, cycle each through its own candidate-string array at a fixed swap rate, staggering each column's final settle frame so they lock left-to-right like a slot machine converging on a decided sentence. From `A_explainer-zhylar-crm-cpq` (reused in `A_best-launch-reel-2026` as a single-slot variant). |
| `wordBuildReveal` | `steps=4, dur_per_step_f=5, ease=expoOut, underline_draw=true` | A string is revealed by progressively increasing the visible substring length in N discrete steps (never per-character, never all at once); if `underline_draw`, a redraws its width to match the new substring on each step. Distinct from `typeOn` (continuous, per-character, caret) and `letterCascade` (animates already-complete text) — this is for a short tagline that should feel "completed via a few deliberate edits." From `A_explainer-zhylar-crm-cpq`. |

## Notes for whoever builds from this file
- Every `hard swap` move above (`treatmentStutterSwap`, `paletteHardSwapPass`) is
  deliberately **not** eased — do not "fix" the lack of a transition; the absence
  of easing is the effect (see `PATTERNS.md` §1.4 and §3.6).
- `nestedFrameTunnelMask`'s ribbon-plank variant is the only entry in this file
  that genuinely needs WebGL/three.js (a per-plank fragment shader driving hue from
  a `uTime`-style uniform). Every other mask/material move here is CSS/SVG-native.
- `maskShapeMorph` and `shapeMorphCollapse`-style chains require **matched point
  counts** across all stage paths — plan this before final art is drawn, not after
  (`B_editors-loop-3d-camera`'s own `avoid:` note).

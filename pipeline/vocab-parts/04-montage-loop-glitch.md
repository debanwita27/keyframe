## 1.11 Loop bookending
A clip's opening and closing states are engineered to match (a mirrored curve, matching content, or a literal pixel-identical frame) so looped playback has no visible seam. Corpus is naturally thin here — 5 distinct disguise mechanisms, no padding.

| move | status | params | description + recipe | source |
|---|---|---|---|---|
| `rackLoop` | built: RackLoop | `blur_px=[18,0], scale=[1.04,1], dur_f=27 (open), mirrored_out_f=16 (close), ease=expoOut` | Background/content opens blurred+scaled-up, sharpens over `dur_f`; the identical curve replays in REVERSE over `mirrored_out_f` at the very end so frame 0 and the final frame match pixel-for-pixel. **Shipped bug, must fix on reuse:** progress must be `t = frame % cycleLength_f` — the shipped version drove progress off raw `frame` with no modulo, so once an outer player loops the composition, frame keeps climbing past the first cycle and blur stays clamped at max forever instead of resetting. | `A_recent-motion-4k-vertical` |
| `crystalShatterLoop` | spec-only | `shard_count=24, burst_dur_f=15 (native 12f@24fps, ease=springSnap), contract_dur_f=10 (native 8f@24fps), final_frame=dot matched to opening seed element` | A sphere bursts outward into N triangular shards via springSnap (damping14/mass0.5/stiffness180), then shards contract back inward to a single point matched in size/color to an established "seed" element from the piece's own frame 0 — hardCut back to frame 0, whole composition wrapped so `durationInFrames` loops seamlessly. ## 1.12 Glitch / strobe / flash as transition disguise
A hard visual event (flash, tone-invert, strobe, datamosh, irregular material swap) substitutes for what would otherwise be a scene-change cut. Flash-length precision matters: sub-11f events are flashes, not shots.

| move | status | params | description + recipe | source |
|---|---|---|---|---|
| `flashCut` | spec-only | `dur_f=2, color=white\|accent` | Solid-color frame(s) at the peak of the motion curve, marking a beat cut. The floor case — anything ≥11f is a shot, not a flash. Already named in MOVE_VOCAB.md; kept. | MOVE_VOCAB.md (pre-existing) |
| `zoomBlurCut` | spec-only | `dur_f=5, scale=[1,1.3], radial_blur=yes, then hard cut` | Scale + radial-blur ramp, then cut — fast montage transition. Already named in MOVE_VOCAB.md; kept. Alias `whipZoomOut` (reverse-direction zoom-OUT variant, `dur_f≈8` native 6f@24fps, `scale: 1→0.35`, heavy motion blur — `B_chromatic-logo-2d3d`). | MOVE_VOCAB.md (pre-existing) |
| `toneInvertFlash` | spec-only | `dur_f=4 (native 3f@24fps), invert=full` — immediately follows a 2-3f `flashCut` whiteout | Full-frame `filter: invert(1)` right after a whiteout flash, punching a negative-space read of the current shape before it resolves via a path-morph. Full sequence (`bloom-invert-morph-transition`): bloomGlow ramp ~5f (native4f) → `flashCut` whiteout ~2-3f (native2f) → `toneInvertFlash` 4f → `morphShape` 10f (native8f) expoInOut — same object persists through huge luma swings, nothing reads as a scene break. | `B_chromatic-logo-2d3d` |

### Conflicts kept apart (families 1.10-1.12)
| move A | move B | how to tell them apart |
|---|---|---|
| `tileCycleGrid` | `cardContentSwap` | Both are the same fixed NxM grid. `tileCycleGrid` cycles each cell independently, staggered, continuously. `cardContentSwap` swaps every cell's content at once, for a single wholesale refresh — corpus explicitly built these as different jobs. |
| `quadrantProofGrid` | `conveyorSlide` | `quadrantProofGrid`'s N channels run different CONTENT TYPES on independent, unrelated schedules (chatbot UI vs. brand mark vs. proof cards). `conveyorSlide` is one row of INTERCHANGEABLE same-shape cards on one shared offset function. |
| `flashCut` | `toneInvertFlash` | `flashCut` = solid-color frame. `toneInvertFlash` = full-frame color INVERSION of the existing image, no solid color. They chain together (`flashCut` then `toneInvertFlash`) but are separate visual events — never collapse into one move. |
| `glitchSwap` | `flashCut` | `glitchSwap` replaces the frame with alternate CONTENT (image/text/inverted layer); `flashCut` replaces it with a flat color. Different mechanism, same 1-2f timescale. |
| `strobeRestyleTransition` | `glitchMaterialMorph` (built: HardSwap) | `strobeRestyleTransition` alternates exactly 2 states on a regular `frame % 2` period, tied to one specific shot boundary (a transition). `glitchMaterialMorph`/HardSwap cycles 6+ states on an IRREGULAR seeded schedule as ongoing ambient re-skinning, not tied to any single cut. |
| `glitchMaterialMorph` (built: HardSwap) | `treatmentCrossfadeSwap` (MOVE_VOCAB_ADDITIONS.md, family 1.4) | HardSwap steps N layers on an irregular seeded schedule and reads as glitch/energy; `treatmentCrossfadeSwap` is an eased crossfade and reads as material transformation. The corpus uses them for different jobs — not interchangeable. |
| `glitchDissolve` | `radialFlareBurst` | Both are >11f ramps, not flashes. `glitchDissolve` resolves FROM chaos TO clean (structure returns by the end). `radialFlareBurst` ramps luminance UP toward a climax with no return to clean — it resolves via a subsequent hard cut, not within its own duration. |
| `rackLoop` / `crystalShatterLoop` / `specularFlashOutroLoop` / `ringWipeLoopClose` / `matchingOpenCloseHold` | (each other) | Five different bookend devices for the same seam-hiding job: mirrored blur/scale curve; shatter-to-matched-seed-dot; light-sweep+fade-to-blank; expanding/contracting ring wipe to an overexposed match; and bare content-match+hold. Pick by shot content, never merge — none is a parameter variant of another. |
